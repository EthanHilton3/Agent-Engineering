# Homework 3c: MCP

## Summary

I turned my final project, **Continuity**, into an MCP server so any AI can use the same tools my app's assistant (the Lorekeeper) uses: my watch history, my goals, and what episode I'm on. Then I connected Claude Code to it and chatted with my own watch history from the terminal. It was really fun and surprisingly useful.

Claude wrote the server and a test script, and I reviewed them. I ran the server and had the conversations myself.

## What MCP is

Before this, every tool I gave an agent was a Python function inside my own agent loop. MCP is a standard instead: a service puts its tools behind an **MCP server** once, and any AI app (the **client**) can connect, ask what tools exist, and call them. Under the hood it's just JSON over HTTP.

## What I built

```
Claude Code (client + the AI deciding what to call)
     |  MCP over HTTP
     v
continuity_mcp.py (MCP server on my laptop)
     |  regular Python calls
     v
Continuity's existing tool code  ->  Supabase (my data) and TMDB (show info)
```

| File | What it does |
|---|---|
| `continuity_mcp.py` | The server. A thin FastMCP wrapper over six of the Lorekeeper's **read-only** tools, signed in as my demo user. Each tool's docstring becomes its description, which is the only "manual" the outside AI gets. |
| `try_continuity_mcp.py` | Calls the server with no AI, to check the server works by itself. |

The files live in my Continuity repo under `mcp/`, since they import the app's backend from there.

## Using it

- **"Am I going to finish Avatar by my deadline?"** Probably not: I'm 24 of 61 episodes in, need 6.6 a week, and have been doing 2.5.
- **"Make me a goal for the Infinity Saga."** It couldn't, because the tools are read-only.
- **"Plan it so I finish by Dec 1."** It made a night-by-night plan around my usual watch nights, treated Thanksgiving as a flex day, and fit Avatar episodes in between movies.

That last one is something my app can't do alone. Continuity knows my history and goals, and Claude knows the Marvel order and when Thanksgiving is. Combining them is the whole point of MCP.

## The one-sentence fix

My first question had a typo ("avatr"), and Claude searched my files and asked which project I meant instead of using Continuity. Claude Code loads MCP tools only when it thinks it needs them (to save tokens), so nothing told it my server was relevant. I had Claude add a one-sentence server description: "this is the user's personal media journal, use it for any question about their shows, movies, books or goals."

| Same question, new session | Result |
|---|---|
| Before the description | Searched my files, then asked me which project I meant |
| After | Glanced at a couple of files, then called Continuity on its own and answered |

## Security and next steps

Right now **nothing checks who's calling**. The server always acts as my fake demo user with a saved password. That's fine only because it's on my laptop, uses fake data, and is read-only.

The real way is **OAuth**, like "Sign in with Google": the AI opens my browser to Continuity's login and approval page, I click Allow, and the AI gets a revocable token instead of my password. FastMCP already supports Supabase for this, but my Supabase project has its OAuth server turned off, and building the approval page would take about 1.5 to 3 hours. So I added it to my plan for after the class. I really want to do it once Continuity is live, along with **write access** ("log that I watched Severance S2 E7"), using the same rule my app already has: the AI only suggests, and nothing saves until the user confirms.

## What I learned

1. **An MCP server can be a thin layer over tools you already have.** The tools took minutes, because the real work was already in my app.
2. **Descriptions are everything to an outside AI.** One sentence decided whether my app got used at all.
3. **Rules have to live in the server, not the prompt.** Claude guessed movie runtimes "from memory" and did schedule math itself, things my app's prompt forbids. Over MCP I don't control the other AI's prompt, so anything important has to be enforced in the server's code.
4. **Tools built for one agent don't fit every agent.** Asked about "all my shows," it had to guess from my goals list, since the Lorekeeper never needed a "list my shows" tool.
5. **The big win is mixing tools.** My data plus Claude's general knowledge made a plan neither could make alone.
6. **Read-only is a great default, and login is the real work.** Read-only made it safe to play with. Making it public safely (OAuth, confirmed writes) is what takes hours.
7. **Test the server without an AI first.** The no-AI script showed the server worked before I had to wonder whether the AI was the problem.

## Final project status: Continuity

The app now has **goals**. I say something like "I want to finish Avatar by Dec 21," confirm a card, and the goal tracks itself from what I log: what's left, runtime left, and whether I'm on pace. A **planner** makes a dated schedule from the nights I usually watch, and new pages show my timeline, my goals, and each goal's progress. Claude also set up a demo account with 11 weeks of history, which the MCP server uses. One safety check I like: when the assistant reports goal numbers, the code checks every number and date against the tool results, so it can't make up progress.

Testing on my laptop showed it worked but didn't feel good yet. A messy memo took over 30 seconds, follow-ups sometimes started a new conversation, and the wording felt like a task tracker. I added a few sessions to fix speed, make it a real chat, and redo the wording before the final evaluation, and I'm working through those now.
