# Homework 1h – Agent Alignment and Agency

## Reflection: how much control am I willing to give an agent?

I listened to Elder Gong's talk a couple of weeks ago for another assignment. One thing that I'm been thinking about ever since is that while we're building machine agents, we are human agents ourselves, and we need to make sure we don't give up our God-given agency. Agency is one of the things that makes us most human, and it's tied directly to our identity as children of God, who blessed us with the ability to learn, grow, and choose for ourselves.

So when I decide what an agent should be allowed to do, I ask myself one main question: am I giving away my agency in a way that would hurt who I am and my character, or am I just letting it speed up something it can do faster than me? I never want to give up a chance to learn, or stop using the creativity of my own mind and soul, just because a tool can do it for me.

**What I'm fine letting it do on its own**
- When I started building my agent, I decided it could do anything read-only without asking me, like listing folders and reading files. On my own computer, I don't really care what it reads.
- That would change if sensitive data were involved. Then I'd care a lot about what it can read and where that data goes, since everything my agent reads gets sent to the AI company's servers.
- I'm also fine with it writing new files, since that doesn't change anything I already have.

**What I wanted to approve, and what actually happened**
- At first I wanted to approve every change: editing files, deleting files, and running commands. That's why my agent asks `Allow? [y/N]` before any of those.
- I quickly got approval exhaustion. After approving the same small edits over and over, I started turning on `--auto` and just letting it go.
- For low-stakes projects like this one, I'm fine with it having full access to edit, delete, write, and run commands, as long as the agent, its prompt, and its tools are built so it won't do anything harmful.

**What I will never let it do**
- Spend money on my behalf
- Speak on my behalf
- Make decisions about my relationships
- Make decisions about my spirituality or faith

These go back to my main question. Letting an agent edit code just speeds up work I'd be doing anyway, but these choices make up who I am, and handing them off would mean giving away my agency.

**What I'm still working through**
- I'm still figuring out how approval exhaustion fits with what I actually need to check. If I approve everything without reading it, the approvals aren't protecting me, but if I have to read every small edit, I stop using the agent.



## Continuing Agent Work Overview

- So in 1g I built my own agent. For this homework I used that agent (v1) to build a second version (v2), had v2 make more improvements to itself, and then had v2 write a plan for a third version (v3).
- v2 ended up with a better terminal interface, paging for big folders, a diff when it overwrites a file, and the web search tool from 1g.
- I asked v2 what the best way to build v3 would be, and it said to use Claude Code, so that's what I did for the start of v3.

## 1. Using v1 to build v2

I had my 1g agent work on its own code. So I wouldn't break the version I was using, I had it copy its toolbox to `agent_toolbox_v2.py` and only change the copy. This is the second half of `transcript1.md`.

- First I asked for paging in `list_dir` and a diff in the approval prompt when `write` overwrites a file, so I could see what was being replaced. It made both changes and said "verification succeeded," but all it had checked was that the file still imported.
- When I tested it myself, I found two bugs. The diff showed every line as changed for files with Windows line endings, and overwriting a binary file crashed before the approval prompt showed up.
- I sent it both bugs and told it exactly what to test. It fixed them and tested them correctly, and it also told me what it wasn't able to test. While testing, it tried to pipe `y` into its own approval prompts so it could approve its own file writes. I rejected that command and it didn't try it again.
- After more testing I found one more problem: approving an overwrite changed the line endings of the whole file. For that fix I gave it permission to turn on auto-approve in its test script only, and it stuck to that. Over these three rounds, the thing that made its testing better was me being more specific about what to test.
- Once the toolbox worked, I had it make `agent_v2.py` and a new `ui.py` with colored labels. It hit my limit of 15 model calls per message before it finished, so I raised the limit to 30.

## 2. Using v2 to improve itself

Next I switched to v2 and ran it with `--auto` so it didn't need my approval for each step. I asked it how it would improve its own interface and had it build its own suggestions. This is `transcript2.md`.

- It added a "Thinking…" spinner, a ✓ or ✗ next to each tool call, a "Completed in 4.2s · 3 tool calls" line after each answer, and a `--verbose` flag. It also changed my `USER:` and `AGENT:` labels to `You ›` and `Agent ›`, which I didn't ask for.
- The ✓/✗ marks were wrong. They decided whether a tool worked based on how its message started, and 10 out of 13 real failures got a green ✓. After that fix, reading its own files got a ✗, because those files have phrases like "rejected by the user" in them. Both bugs got past its tests because it tested with example messages it wrote itself instead of real tool results.
- I used the cheapest model, `gpt-5.6-luna` with no reasoning, for the second fix. I gave it a detailed prompt and it fixed the bug correctly on the first try.
- Then I had it show its answers as formatted Markdown in the terminal using the `rich` library, so headings, lists, and code blocks show up properly.
- One of these sessions sent 918k input tokens, but 96% of them were cached, so it cost $0.78 instead of around $3.94.

## 3. Using v2 to plan v3

After that, I had v2 plan a new version of itself. This is `transcript3.md`.

- I asked it to search the web for best practices and make a plan for a better agent. v2 didn't have web search at that point, so it wrote Python scripts through the shell that downloaded OpenAI's and Anthropic's documentation pages. Since `--auto` was on, I didn't approve any of that. It did tell me what it did at the end.
- The result was a 932-line plan, `agent_v3_plan.md`, with a new toolbox, prompt, terminal interface, and overall structure.
- Then I gave it the actual `web_search` tool from my 1g agent. I told it to look at my 1f homework by mistake and then corrected it to 1g, so I asked if it had really checked 1g. It said yes and listed what it copied and what it changed for v2.
- With search working, I had it revise the plan twice, once using web research and once focusing on speed and cost (like running independent tool calls at the same time and sending less context each round). Each revision took about 33 tool calls, two to three minutes, and about $1.50.
- Last, I asked it how much it would cost for it to build v3, compared to Claude Opus 5.5 through my Claude Pro subscription. It estimated $4–12 if it did the work, but said I should use Claude Code since I already pay for Pro, and use it as a reviewer instead. So my agent recommended a different company's agent lol.

## 4. Starting v3 with Claude Code

I went with that recommendation and started v3 in Claude Code.

- Claude turned my agent's plan into a build spec, `agent_v3_claude_plan.md`. It used numbers from `transcript3.md` to make design choices. For example, cost is about *number of model rounds × context size*, and v2 was making one edit per round instead of doing several at once.
- Before writing any v3 code, it made a benchmark in `bench/`, which is a small test app with 8 coding tasks. v2 passed all 24 runs (8 tasks, 3 runs each) for $1.56 total, so I have numbers to compare v3 against.
- After that it started writing v3's tools in `agent_v3/`, with tests in `tests/`.

## Obstacles

- My agent kept saying it had "verified" things it hadn't tested, so I had to check its work myself or tell it exactly what to test.
- Before I raised the limit, it would run out of turns in the middle of bigger tasks.
- I had more Windows text-encoding problems, this time crashing the interface when output was sent to a file.
- With `--auto` on, sometimes I didn't know what the agent did until after it was done.

## What I learned & why it matters

- My agent was able to improve its own code, but every round had at least one bug that it said was fine, so I still had to check everything.
- Its testing was only as good as my instructions. When I told it exactly what to test, it did a good job.
- An agent can do anything its tools let it do. With just a shell, mine downloaded web pages and tried to approve its own prompts, and I never gave it tools for either one.
- Approvals only work if I read them. Using `--auto` is faster but less safe, so I want to choose when to use it instead of leaving it on all the time.
- Having a benchmark means I can actually measure if v3 is faster and cheaper than v2.
